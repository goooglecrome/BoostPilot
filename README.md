# BoostPilot

**A Windows gaming and PC optimisation control centre.**

This repository contains two separate Windows applications. The original BoostPilot remains the primary app and keeps its own installer and update channel.

## BoostPilot website

The static product and downloads website is in `website/`. It is ready to deploy with Cloudflare Pages. See `website/README.md` for the setup steps; set the Pages root directory to `website`, use no build command, and use `.` as the build output directory.

## Original BoostPilot (OG)

The original source project is packaged as `BoostPilot_SourceOnly_v1.2.0.zip`.

1. Open the repository's **Actions** tab.
2. Choose **Build BoostPilot for Windows**.
3. When the workflow succeeds, download the `BoostPilot-Windows-Installer` artifact.

The original installer and updater use the repository's normal GitHub Releases channel. Do not publish the Claude Edition as the latest normal release.

## BoostPilot Claude Edition

A separate WPF app built from the Claude-created source, stored under `ClaudeEdition/`.

1. Open the repository's **Actions** tab.
2. Choose **Build BoostPilot Claude Edition**.
3. Run the workflow.
4. When it succeeds, download the `BoostPilot-Claude-Edition-Installer` artifact.

Claude Edition has a different executable name, installation directory, restore database, installer AppId, workflow and artifact. It does not replace OG BoostPilot and is not published as the latest GitHub Release, so the OG updater remains independent.

## Safety principles

- Review changes before applying them; don't assume a generic tweak improves every PC.
- Preserve a restore path for changes that can be reversed.
- Do not disable Windows Defender, Windows Update, firewall protections, or essential services.
- Do not expose voltage, RAM timing, or fan-control settings without hardware-specific validation.
- Report tasks as complete, skipped, or failed based on their actual result.
- Do not claim an FPS or ping improvement unless it is measured.

Both applications need to be tested on Windows hardware before they should be treated as production-ready. Installers generated by the current workflows are not digitally code-signed.
